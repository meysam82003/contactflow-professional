# قابلیت‌ها و مرزهای نسخه ۳.۴

نسخه ۳.۴ یک موتور مشترک Import/Merge به `web/` اضافه می‌کند؛ بنابراین Telegram Mini App، PWA، Android و پوسته‌های Windows/Linux/macOS از یک منطق و یک مدل داده استفاده می‌کنند.

## Import و پاک‌سازی

- انتخاب و Drag & Drop هم‌زمان چند فایل و Merge آن‌ها در یک فهرست
- CSV، TSV، TXT، VCF، JSON، XLSX و XLS (شامل OLE/BIFF، SpreadsheetML و HTML)
- ZIP شامل فایل داده و عکس‌های JPG/PNG/WebP، با کنترل تعداد Entry، حجم بازشده و نسبت Zip Bomb
- هشدار فایل خالی، بزرگ، فرمت ناشناخته و ZIP/XLSX خراب
- Progress زنده و سقف حافظه برای تحلیل بسیار بزرگ
- تشخیص شهر از نام فایل؛ برای مثال `Qom.txt` به `قم` تبدیل می‌شود
- فرهنگ نام شهرهای رایج و ترانویسی آفلاین لاتین به فارسی به‌عنوان fallback
- حذف فاصله، پرانتز، خط تیره و کاراکتر اضافه شماره
- تبدیل شماره محلی ایران به E.164 و تشخیص کشور از Calling Code
- تشخیص شهر/استان شماره ثابت ایران از Area Code
- تشخیص موبایل، تلفن ثابت و نوع نامشخص
- اعتبارسنجی طول National Number بر اساس کشور تشخیص‌داده‌شده
- جداسازی نام شرکت با Keywordهای فارسی و انگلیسی
- ثبت `source`، `sourceFiles`، `importIds` و یادداشت تاریخ/فایل روی رکورد
- نمایش اختیاری اعداد فارسی؛ مقدار ذخیره‌شده همیشه E.164 لاتین باقی می‌ماند

XLS/XLSX ابتدا با Parser سبک Streaming خوانده می‌شود و برای قالب‌های باینری، Workbookهای پیچیده یا fallback از SheetJS CE نسخه پین‌شده استفاده می‌کند. سقف ردیف و اندازه فایل همچنان قبل از Merge اعمال می‌شود.

## Merge، گزارش و بازگردانی

- مرحله تحلیل همیشه بدون نوشتن در دیتابیس اجرا می‌شود
- Dry-run پیش‌فرض و دکمه ثبت جداگانه
- مقایسه رکورد قدیمی و ورودی جدید پیش از Merge
- انتخاب سیاست «قدیمی»، «جدید» یا «تکمیل هوشمند» برای هر تعارض
- Smart Fill فقط فیلد خالی را پر می‌کند و داده پرشده قدیمی را Overwrite نمی‌کند
- Dedupe بر اساس شماره E.164 و ایمیل معتبر
- گزارش جدید/تکمیل/تکراری/نامعتبر برای هر فایل
- گزارش تکراری به‌تفکیک شهر، نام خانوادگی و دامنه ایمیل
- نمودار تعداد مخاطب هر شهر
- مرتب‌سازی نتیجه بر اساس شهر و سپس نام
- خروجی فقط مخاطبین جدید آخرین Plan
- گزارش Excel و صفحه Print-friendly برای Save as PDF سیستم
- Undo مستقل هر Import بر پایه Delta ذخیره‌شده
- Rollback کامل آخرین Merge ثبت‌شده
- حذف گروهی یک منبع با Dry-run؛ رکورد چندمنبعی حفظ می‌شود
- شماره‌گذاری مجدد همه ردیف‌ها پس از پاک‌سازی
- تاریخچه Import/Merge و Audit Log محلی

## دفترچه دستگاه، عکس، OCR و Watch Folder

- Web Contact Picker فقط مخاطبینی را می‌گیرد که کاربر در UI سیستم انتخاب می‌کند
- APK اندروید با دکمه صریح، Runtime Permission از `READ_CONTACTS` درخواست و دفترچه را محلی وارد می‌کند
- APK اندروید (حداقل API 23) OCR کارت ویزیت را با ML Kit روی دستگاه اجرا می‌کند
- در مرورگر دارای `TextDetector` همان OCR به‌صورت Capability-gated فعال است
- عکس‌های ZIP بر اساس نام فایل/شماره به مخاطب مرتبط و در IndexedDB محلی ذخیره می‌شوند
- Watch Folder از `showDirectoryPicker` استفاده می‌کند و فقط با اجازه کاربر و تا زمانی که برنامه باز است هر ۶۰ ثانیه اسکن می‌شود
- Web Share، Android System Document Picker و دانلود استاندارد برای تحویل خروجی وجود دارد

Telegram Mini App یا یک صفحه وب مجاز نیست دفترچه کامل گوشی را پنهانی بخواند. در Mini App باید Contact Picker پشتیبانی‌شده یا Import فایل استفاده شود؛ دسترسی کامل دفترچه در APK اندروید نیز فقط پس از تأیید مجوز کاربر است.

## Telegram

- صفحه مخاطبین حساب از User Session مستقل و متد رسمی `contacts.getContacts` نسخه ۳.۳ حفظ شده است
- Checker شماره‌های موجود در دیتابیس از `contacts.importContacts` در همان User Session استفاده می‌کند
- مخاطبین موقت هر Batch پس از نتیجه با `contacts.deleteByPhones` پاک می‌شوند
- هر اجرا حداکثر ۵۰۰ شماره دارد و FloodWait باعث توقف می‌شود
- نتیجه `matched` با برچسب «تلگرام‌دار ✓» در ContactFlow ذخیره می‌شود
- نتیجه‌های `not_returned` و `retry` جدا ذخیره و خروجی گرفته می‌شوند
- فیلتر اصلی مخاطبین و آمار درصدی matched اضافه شده است
- نتیجه Telegram داخل رکورد `contacts` است و در Backup محلی بین Windows و Mobile منتقل می‌شود

`not_returned` الزاماً به معنی «تلگرام ندارد» نیست؛ Privacy شماره یا رفتار API می‌تواند مانع بازگشت Match شود. UI و فایل خروجی آن را «برنگشته/نامشخص» نام‌گذاری می‌کنند.

`Telegram.WebApp` و Bot API فهرست کامل مخاطبین حساب را ارائه نمی‌کنند و Session داخلی اپ Telegram نیز در اختیار JavaScript نیست. مشاهده دفترچه حساب به API ID/Hash رسمی و QR User Session مستقل نیاز دارد.

## مدل داده ۳.۴

نسخه IndexedDB به ۴ ارتقا یافته است و Storeهای زیر افزوده شده‌اند:

- `merge_runs`: Delta، گزارش، وضعیت Commit/Rollback و Undo فایل‌ها
- `contact_images`: عکس‌های Import شده و ارتباط با شماره/Import
- `watch_state`: Handle و آخرین وضعیت Watch Folder

روی `contacts` نیز Indexهای `source`، `sourceFiles`، `importIds`، `telegramStatus`، `country` و `phoneType` ایجاد می‌شود. Backup نسخه ۶ این Storeها و وضعیت Telegram داخل مخاطبین را پوشش می‌دهد؛ Session حساس Telegram همچنان در Backup عادی قرار نمی‌گیرد.
